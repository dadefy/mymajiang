# 内部联网测试指引

目标：**让同一个局域网（或拿到同一个网址）的人今天就能打开页面开始打牌**，
不需要 Android 工具链、不需要打包 APK、不需要上架。

浏览器调试客户端复用 `apps/client` 里已经过单元测试的业务层（页面流转、断线重连、令牌持有、
群聊实时推送、图片与语音上传、幂等重试），所以它验过的行为与最终 LayaAir 版本一致 ——
区别只在渲染。

---

## 一、在一台机器上把服务端跑起来（这台就是"服务器"）

```powershell
cd <项目目录>
pnpm install                                    # 首次
pnpm --filter @mianyang-mahjong/client build    # 调试客户端是编译产物，必须先构建
pnpm --filter @mianyang-mahjong/server build
```

`apps/server/.env` 里这两项要确认：

```
PORT=3000
HOST=0.0.0.0          # 让局域网内其它机器能连上；写 127.0.0.1 就只有本机连得上
ADMIN_ID=你的账号
ADMIN_PASSWORD=足够长的密码
```

> ⚠️ `HOST` 是**最容易漏的一项**。写成 `127.0.0.1` 时服务端只监听回环地址，
> 别人打开网址会「无法连接」，而且本机自测一切正常，很容易查错方向。
> 用 `Get-NetTCPConnection -State Listen -LocalPort 3000` 看实际监听地址是不是 `0.0.0.0`。

查本机局域网 IP：

```powershell
ipconfig | Select-String "IPv4"
```

启动：

```powershell
pnpm --filter @mianyang-mahjong/server start
# 或者直接： node apps/server/dist/main.js
```

看到这几行就是成功了：

```
[admin] http://127.0.0.1:3000/admin
[websocket] 与 HTTP 共用端口 3000
[debug client] http://127.0.0.1:3000/debug
```

**单端口设计**：HTTP 与实时通道都在 3000 上，页面按自己的 `location.origin` 推导 `ws/wss`，
所以不需要配 `PUBLIC_HOST` —— 隧道、反向代理、HTTPS 全都自动正确。

## 二、启动后先自检，全绿再叫人

```powershell
cd apps/server
node --env-file=.env scripts/smoke.mjs
```

它会真的发 HTTP 请求，逐项确认：调试页面能打开、入口脚本与它引用的每个模块都能取到、
管理员流程（登录 → 签发密钥 → 激活建号 → 发积分）能走通、建房与群聊接口正常，
以及**图片与语音的直传地址能不能签发**（没配对象存储时这两项会是 501，
那意味着内测期间发不了图和语音）。

`--env-file=.env` 是为了让它自己读管理员账号密码，不用把密码写进命令行。

**全绿再叫人来测。**

## 三、给每个测试的人发两样东西

1. **网址**：`http://<你的局域网IP>:3000/debug`
2. **一把邀请密钥**

### 密钥怎么签发，以及为什么必须当场记账

服务端**只存密钥的哈希**（明文不落库、不出网）—— 这样即使数据库被拖走，也不会导致所有账号同时失守。
代价是：**签发之后，后台再也看不到明文**，列表里只有前 8 位提示位。

所以要靠签发这一侧记账。用这个脚本签发，它会**把明文追加进本地台账**：

```powershell
cd apps/server
node --env-file=.env scripts/issue-keys.mjs 4 "给测试组"
```

- 台账：`apps/server/.keys-ledger.txt`（**已在 .gitignore 里**，内容是明文，不要外传）
- 加 `--quiet` → 只在台账留档、屏幕不打印（批量签发时用）
- 查回明文：`Get-Content apps/server/.keys-ledger.txt`

> ⚠️ **一把密钥只能建一个账号，且密钥丢失等于账号丢失**（没有找回流程）。
> 所以台账文件实际上是你**唯一的密钥明文备份** —— 签完记得确认它写进去了。

### 为什么不在后台直接显示明文

那需要服务端落库保存明文，而**明文一旦落库，数据库泄露就等于所有账号同时失守**。
把明文留在你自己的台账文件里，风险范围只有一个不进仓库、不参与部署的文件。
这是 `PROJECT_STATUS.md` 第 11 节第 16 条的硬规则；要改它属于**改规格**，需要先想清楚上面这个代价。

### 重启之后：一条命令把账号补回来

现在跑的是**内存模式**（`.env` 里没有 `DATABASE_URL`），服务端一重启，下面这些**全部清零**：

- 账号，以及已经发放的积分
- **已签发的密钥记录** —— 注意台账里那些明文密钥会**随之失效**，因为服务端不认识它们了
- 房间、群聊、对局状态

所以**每次重启之后**，用这一条命令重建测试账号（签发密钥 → 建号 → 发积分，一次做完）：

```powershell
cd apps/server
node --env-file=.env scripts/seed-testers.mjs 张三 李四 王五 赵六
```

它会打印每个人的**用户 ID 与密钥**（并写进台账），可以直接发给对应的人。
`--points 5000` 改发放额度（不能低于 500）；`--quiet` 则只在台账留档。

> **想要重启不丢数据**就得配 PostgreSQL（`.env` 填 `DATABASE_URL` 再跑 `db:migrate`），
> 但本机目前没装 —— 验收期间用上面这条命令重建，比装数据库快得多。
> 也因为这一点：**验收期间尽量攒着改代码、一次重启**，别改一处重启一次。

## 四、⚠️ 每人建号后，你要给他们的账号发积分

**这是最容易卡住的一步**：规则要求**至少 500 积分才能进房**，而新账号是 0 分，
所以**不发积分他们连房间都建不了**，只会看到一个 409 错误。

管理后台 →「用户管理」→ 找到那个账号 →「积分」→ 填 `2000`，原因写"内测发放"。

## 五、开始

四个测试者各自打开那个网址：

1. 输入各自的邀请密钥 → 第一次会要求填昵称 → 进主页
2. **一个人**点「建一个新房间」，把房间 ID 发给另外三个人
3. 另外三个人在主页输入房间 ID → 点「加入」
4. 四个人都点「我准备好了」，房主点「开始对局」
5. 按提示走：换三张 → 定缺 → 行牌（点手牌即出牌）

刷新页面不会掉线（令牌存在浏览器里，会自动恢复）。真掉线了会按 0.5/1/2/4/8 秒退避重连。

## 六、逐项验收清单

> 建议照这个表走一遍，边做边打勾。**"两台设备"的意思是操作的那台和另一台观察的**，
> 用来验证实时推送真的到了对方那里。

### A. 登录与主页（每台设备都做）

- [ ] 打开网址 → 看到密钥输入页
- [ ] 输入密钥 → 首次要求填昵称头像 → 进主页
- [ ] 主页显示昵称、10 位用户 ID、积分
- [ ] 刷新页面 → 不用重新登录

### B. 对局（四个人一起，跑满 8 局）

- [ ] 一人建房，其余三人按房间 ID 加入
- [ ] 四人点「我准备好了」→ 房主开局
- [ ] 换三张：**只能选同花色的三张**（选不同花色会被拦）
- [ ] 定缺：选定后，缺门牌没打完之前只能打缺门牌
- [ ] 行牌：轮到自己时点手牌即出牌，别的玩家手牌看不到
- [ ] 碰 / 直杠 / 暗杠 / 补杠 / 点炮胡 / 自摸胡：出现操作按钮时点击生效
- [ ] 单局结算浮层显示分数变化
- [ ] 打满 8 局 → 整场结算
- [ ] **四个人把分加起来等于 0**（零和，这是最该核对的数字）
- [ ] 战绩里能看到这一场

### C. 群聊

- [ ] 建群 → 另一台设备按 **8 位群号**加入
- [ ] 发文字 → **另一台设备不刷新就能看到**（这是实时推送，不是轮询）
- [ ] 撤回自己的消息 → 两台都变成「[消息已撤回]」
- [ ] 超过 2 分钟的消息：撤回按钮消失（服务端会拒）
- [ ] 往上翻能加载更早的消息（游标分页）

### D. 图片

- [ ] 点「图片」选一张照片 → 发送
- [ ] 另一台设备收到这条消息（目前显示「[图片]」占位文字，还没有预览）
- [ ] 传一张超过 5 MB 的图 → 提示「图片不能超过 5 MB」，且没有发出去

### E. 语音（需要 HTTPS，见第七节）

- [ ] 点「语音」→ 允许麦克风 → 按钮上开始显示秒数
- [ ] 再点一下 → 停止并发送
- [ ] 另一台设备收到「[语音 N 秒]」
- [ ] 录到 60 秒会**自动停止并发送**（服务端只收 1–60 秒）

### F. 异常与恢复

- [ ] 打牌中途关掉 WiFi → 提示「连接已断开，正在重连…」
- [ ] 恢复网络 → 自动重连，牌局状态还在
- [ ] 打牌中途关掉浏览器 → 重新打开 → 牌局还在（服务端快照续打）
- [ ] 服务器重启后（内存模式）账号会丢 —— 这是设计如此，要留存就配 PostgreSQL

## 七、语音为什么需要 HTTPS

浏览器只在**安全上下文**里给麦克风权限。`http://192.168.1.164:3000` 是明文 HTTP，
`getUserMedia` 会直接失败，页面上会显示「录不了音：需要允许麦克风权限，且页面要在 HTTPS 或 localhost 下」——
**这不是代码问题**。

三个选择：

**A. 把内网地址加进 Chrome 白名单（最快，零依赖）**

1. Android Chrome 里打开 `chrome://flags/#unsafely-treat-insecure-origin-as-secure`
2. 输入框填 `http://192.168.1.164:3000`，把开关设为 **Enabled**
3. 重启浏览器，语音就能用了

**B. 用隧道拿一个 HTTPS 地址**（同时能让不在同一局域网的人参与）

把 3000 端口通过隧道暴露出去，拿到 `https://xxx` 后所有人访问这个地址。
注意免费版的连接数 / 流量限制。

**C. 真机装自签证书**（最麻烦，内测阶段不建议）

> **图片上传不受这条限制**（它不需要安全上下文），所以不做 HTTPS 也能验图片与文字。

## 八、与最终 APK 的关系

| | 浏览器调试客户端 | LayaAir APK（`apps/apk`） |
| --- | --- | --- |
| 用途 | **内测**：打开网址就能玩 | 上线给玩家 |
| 业务层 | `apps/client`（共用） | `apps/client`（共用） |
| 网络适配 | `apps/client/src/browser/transports.ts` | `apps/apk/src/laya-transports.ts` |
| 图片/语音 | `browser/` 下的标准 Web API 实现 | 参考同目录；**原生环境下选图与录音需要另做桥接** |
| 需要工具链 | 无 | LayaAir + Android 打包 |

两边共用同一套业务层（连录音器都是同一份），所以内测期间发现的行为问题，修一次两边都受益。

**已知的两处"只在浏览器能用"**：选图（`<input type="file">`）与录音（`MediaRecorder`）
都依赖标准 Web API，打包成原生 APK 时没有对应实现，会退化成「发不了图 / 录不了音」——
不报错、不崩，但功能不可用。要上真机发图发语音，得补原生相册与录音桥接。

## 九、LayaAir Web 版（可选，但更接近上线版本）

`/debug` 是手写的调试界面；LayaAir 那边才是**最终 APK 里真正用的 UI**。
把它构建成 Web 平台挂到服务端，就能用手机验到真实的界面与牌桌渲染。

### 构建（需要 LayaAir CLI，**不需要**装那个几百 MB 的 IDE）

```powershell
# 1. 装 CLI（一次性；只往 %USERPROFILE%\.layaair 写）
iwr https://raw.githubusercontent.com/layabox/layaair-cli/master/install.ps1 | iex
& "$env:USERPROFILE\.layaair\layaair.cmd" install 3.4.0

# 2. 构建 Web 版。产物落在 apps/apk/release/web（不进仓库）
& "$env:USERPROFILE\.layaair\layaair.cmd" --version=3.4.0 build web -p apps/apk
```

`layaair build --list-platforms -p apps/apk` 可以看到支持的全部平台（web / android / ios /
windows / 各家小游戏 等 19 个）。

### 访问

服务端会把产物挂在 `/app`：

| 入口 | 地址 | 说明 |
| --- | --- | --- |
| LayaAir Web 版 | `http://<服务器IP>:3000/app` | 真正的渲染层，最接近 APK（会自动跳到 `/app/`） |
| 调试客户端 | `http://<服务器IP>:3000/debug` | 手写界面，功能验证最方便（`/` 重定向到这里） |

> **别把 `/app/` 结尾那个斜杠去掉。** LayaAir 生成的 `index.html` 用的是**相对路径**
> （`libs/laya.core.js`、`js/index.js` 这种，不是 `/app/libs/...`）。访问 `/app` 时浏览器会把
> `app` 当成**文件**，相对路径就按站根解析 —— 请求打到 `/libs/laya.core.js`，**整页资源全 404**。
> 服务端已经加了 `/app` → `/app/` 的 302，正常不会遇到；但如果自己拼 URL 或做反代，
> 要保证最终落在带斜杠的地址上。

**为什么必须由服务端提供**：客户端按 `location.origin` 推导 API 与实时通道地址，
**同源**才连得上；换个端口不仅地址不对，还会撞上跨域。

没构建 `/app` 也能正常存在 —— 它只会返回 404 并告诉你该跑哪条命令，不影响 `/debug`。

### 这一版能验到什么

- 750×1334 竖屏布局、四个页面（密钥登录 / 资料 / 主页 / 房间）的真实渲染
- 牌桌：真实牌面、点击选牌、换三张、定缺、出牌、结算浮层
- 群聊页面的消息列表与输入

### 这一版验不到什么

`/app` 是 **Web 平台**，所以选图与录音走的仍是浏览器实现（`<input type="file">` 与
`MediaRecorder`）—— 能验流程，但**验不到「原生 APK 上能不能选图/录音」**。
要验那个得构建 `android` 平台，而它需要 **JDK + Android SDK**（本机目前都没装）。

## 常见问题

| 现象 | 原因 |
| --- | --- |
| 别人打不开网址 | `.env` 里 `HOST` 还是 `127.0.0.1`；或者 Windows 防火墙拦了 3000 端口 |
| 能进主页但一直"断线" | 少见：单端口部署下 `socketUrl` 留空由前端推导，正常应自动正确；若配了 `WEBSOCKET_URL` 之类的旧配置，清掉它 |
| 建房报 409「至少 500 积分」 | 还没给这个账号发积分，见第四节 |
| 发图片/语音报「服务器没有开启图片上传」 | 服务端没配对象存储（COS 或本地驱动），跑一遍第四节的自检就能确认 |
| 录不了音 | 页面不是 HTTPS / localhost，见第七节 |
| 手机能发文字但发不了图 | 检查是否用了「微信内置浏览器」打开 —— 它限制较多，建议用系统浏览器或 Chrome |
| 战绩是空的 | 内存模式（`DATABASE_URL` 为空）没有历史可查，这是设计如此；要留存战绩就配 PostgreSQL |
| 服务器重启后账号没了 | 内存模式重启丢数据。要让账号留下来就配 `DATABASE_URL` |
