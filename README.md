# 绵阳血战麻将


网页操作按钮仅在玩家有对应操作时显示于该玩家手牌上方；出牌需首次点击抬高选中、再次点击同一张牌确认。点击另一张只改选，同牌面不同实体牌分别选中；回合切换自动清除选择。


四家头像按牌桌方位显示，头像下方为本局净输赢（来自服务端事件账本，换局归零），侧边显示庄家及定缺花色；未设置或加载失败的头像使用灰色昵称占位。


网页四家同屏牌桌按四方布局显示：外圈手牌、内圈碰杠、中央四方弃牌区；东南西北方向盘高亮当前操作方，中心显示服务端超时截止时间对应的倒计时，右侧显示余牌。窄屏保留四方布局，可横向滚动。


换三张按实体牌计数：同花色即可包含重复牌面（如 1万、1万、3万），每张独立选择，提交数量不能超过手中实际张数；已提交后等待其他玩家，不能重复提交。


胡牌亮牌规则（2026-09-16 确认）：前两家胡牌后仅标记已胡，不向其他玩家公开手牌；第三家胡牌结束本局（牌墙耗尽仍按流局结算）。本局结算统一亮出四家手牌与副露，逐家列出本局净输赢，零分也显示。胡牌牌面保存在服务端快照中，支持重启恢复。

Android 麻将项目基础工程。第一版仅支持规则版本 `MIANYANG_XZ_1_0`。

完整进度、接口清单、已知限制与后续顺序见 [`docs/PROJECT_STATUS.md`](docs/PROJECT_STATUS.md)。
参与开发前请先读 [`docs/CONTRIBUTING.md`](docs/CONTRIBUTING.md)：版本控制现状、分工边界、完成的定义，以及给新协作者可直接粘贴的开场提示词。

## 当前阶段

- 已建立 TypeScript 工作区。
- 已实现共享规则配置、牌型基础判断、番数计算和积分结算。
- 已实现对局引擎（packages/rules/src/game.ts）：固定种子牌墙、发牌、换三张、定缺、摸打、碰/直杠/暗杠/补杠/抢杠、点炮胡/自摸胡/一炮多响、过手胡、最后 4 张有胡必胡、血战到底三家胡、流局查花猪/查大叫/退税，全程结算事件账本零和校验。
- 服务端已接入：一次性邀请密钥登录（内测）、管理员积分、房间状态机 REST API（创建/加入/离开/准备/开局/解散投票）和群聊 REST API（建群/入群/消息/撤回/管理）。不再使用手机短信验证码，也没有注册申请与人工审核。
- 已实现通过唯一 10 位用户 ID 精确搜索、好友申请/处理、好友列表和删除好友；公开接口不返回密钥哈希与积分。
- 已提供管理端用户列表、封禁解封、积分流水与撤销、管理员操作审计、邀请密钥签发/列表/撤销接口；签发与撤销密钥仅限超级管理员。
- 服务端已接入 PostgreSQL 连接池、串行数据库迁移、数据库健康检查及进程优雅关闭；生产环境强制配置数据库连接。
- 注册申请和用户账号已切换为 PostgreSQL 写穿缓存：启动时恢复数据，注册、审核、封禁、积分调整、开局和最终结算在响应前刷盘。
- 已接入 WebSocket 实时通道（apps/server/src/ws.ts 零依赖实现 RFC 6455 + ws-server.ts 驱动对局引擎）：4 客户端通过 WS 绑定房间、开局、换三张、定缺、行牌，服务端向每个玩家推送脱敏状态（不含他人手牌）与允许操作集合。
- 已实现整场 8 局连续推进、15 秒行牌/8 秒响应超时托管，以及 120 秒断线重连窗口。
- 已实现积分流水（point_ledger）与管理员审计（admin_audit_log）的 PostgreSQL 持久化：调整积分时账号余额与流水、封禁解封时账号状态与审计记录分别在同一个事务内提交；所有 PostgreSQL 仓库共用一条有序写队列，HTTP 响应返回前统一落盘，进程退出前也会 flush。服务启动时读回历史流水与审计，撤销判定和审计查询在重启后依然有效。
- 已实现好友与群聊的 PostgreSQL 持久化（postgres-friend-store.ts / postgres-group-store.ts）：领域服务仍负责规则裁决，每次变更后排队落盘；接受好友时申请与关系同事务写入，建群时群信息与群主成员同事务写入，转让群主时群信息与两个成员记录同事务写入。启动时读回全部好友申请、群组、群成员与群消息，社交数据重启不丢失。
- 已实现房间与牌局记录的 PostgreSQL 持久化（postgres-room-store.ts）：建房、加入、准备、开局、逐局结果、解散与最终结算全部落盘；每局记录赢家座位、下一局庄家、分数变化与服务端结算事件；结算时四名玩家的余额与四笔 `match_settlement` 积分流水在同一个事务内写出。启动时会恢复等待中的房间（清空准备状态）并把重启前进行中的牌局按已完成局数结算结束，避免把牌局从头重放。
- 数据库迁移已升级为可追加的版本目录 `apps/server/db/migrations/`，迁移执行器按文件名升序执行未应用的版本。
- 已实现一次性邀请密钥登录（postgres-invitation-key-store.ts / invitation-key-codec.ts）：开发方（超级管理员）批量签发形如 `MYMJ-XXXX-XXXX-XXXX-XXXX` 的密钥，明文只在签发响应里出现一次，系统只存 SHA-256 哈希与前 8 位提示位；内测用户首次激活即建号并绑定，之后同一把密钥就是登录凭据。「一把密钥只能建立一个账号」由 `users.invitation_key_hash` 的 UNIQUE 约束保证；已绑定的密钥不能撤销（撤销等于锁号）。不再使用手机短信验证码，注册申请与人工审核已移除。
- 已提供战绩查询：`GET /v1/matches` 返回本人参与过的对局（含各玩家座位、原始分与实际上分），`GET /v1/rooms/:roomId/history` 返回某一场的逐局明细与服务端结算事件（仅参与者可读）。只把真的打过至少一局的对局算作战绩；没有配置数据库时两个接口返回 `501 MATCH_HISTORY_UNAVAILABLE`。
- 已实现重启续打：`packages/rules` 的 `MahjongGame` 支持完整状态快照与恢复（`serialize()` / `MahjongGame.restore()`），服务端在每次状态变化后把进行中那一局写入 `match_round_states`，重启后玩家重连即按存档接着打；存档属于上一局时改为开下一局。快照含牌墙与全部手牌，只留在服务端。
- 群聊已改为 WebSocket 实时推送：认证后 `group-subscribe` 订阅群，新消息、撤回、群公告、全员禁言开关会立刻推给在线成员，被移出群的成员立刻停止接收、群被解散时订阅一并作废。每次广播都会重新确认成员身份。
- 群管理已补齐：`GET /v1/groups` 按最近活跃排序返回我加入的群，支持邀请好友入群（只能邀请好友、重复邀请幂等）、主动退群（群主退出时移交群主，最后一人退出群即解散）与群主解散群。
- 下一阶段：APK 牌桌客户端（LayaAir）的渲染层、对象存储。
- 客户端业务骨架已完成（apps/client）：REST 调用、实时通道（断线重连并重放 auth 与群订阅）、密钥登录 → 主页 → 房间 → 行牌的页面流。核心不依赖 LayaAir 或 DOM，只产出纯数据页面状态，环境差异收在两个传输接口里；与渲染层的对接方式见 apps/client/README.md。
